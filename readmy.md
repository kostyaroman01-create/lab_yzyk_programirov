1. Если участвуют типы с плавающей точкой:
   * Если один из операндов long double $\rightarrow$ второй приводится к long double.
   * Иначе если один double $\rightarrow$ второй приводится к double.
   * Иначе если один float $\rightarrow$ второй приводится к float.

2. Если оба операнда целочисленные (после Integral Promotion):
   * Если знаковость совпадает: наименьший размер приводится к наибольшему (например, int $\rightarrow$ long).
   * Если беззнаковый тип имеет размер/ранг не меньше знакового: знаковый приводится к беззнаковому (например, int + unsigned int $\rightarrow$ оба становятся unsigned int).
   * Если знаковый тип имеет больший ранг и может вместить все значения беззнакового типа: беззнаковый приводится к знаковому.
   * Иначе: оба операнда приводятся к беззнаковому варианту знакового типа.

3. Преобразования указателей (Pointer Conversions):
   * Приведение к void*: Указатель на любой объект или void неявно преобразуется в void* (с сохранением cv-квалификаторов const/volatile).
   * Нулевой указатель (Null Pointer): Литерал 0, NULL или nullptr неявно преобразуется в любой тип указателя или указателя на член класса.
   * Приведение базового и производного классов (Upcasting): Указатель или ссылка на производный класс (Derived* / Derived&) неявно преобразуется в указатель или ссылку на открытый базовый класс (Base* / Base&), если базовый класс доступен и однозначен.

4. Qualification Conversions (Преобразования квалификаторов):
   * Разрешено неявное добавление квалификаторов const или volatile.
   * Пример: int* неявно преобразуется в const int*, но наоборот (const int* в int*) неявно сделать нельзя.

5. Преобразование в логический тип (Boolean Conversions)
Любой арифметический тип, тип перечисления (enum), указатель или указатель на член класса может быть неявно преобразован в тип bool:
   * Нулевое значение, nullptr или нулевой указатель превращаются в false.
   * Любое ненулевое значение или валидный указатель превращаются в true.

6. Пользовательские преобразования (User-Defined Conversions)
Если в выражении участвуют пользовательские классы, C++ может выполнить не более одного пользовательского преобразования в цепочке неявных приведений.
   * Конструкторы преобразования: Конструкторы, которые могут быть вызваны с одним аргументом (и не помечены ключевым словом explicit).
   * Операторы приведения типа: Методы класса вида operator TargetType() const, не помеченные как explicit.

1.Объяснение работы:
  Строка a * b (int * int):
* Оба операнда имеют одинаковый тип int.
* Выполняется стандартное умножение знаковых чисел: (-1)* 1 = -1.
* Результат имеет тип int и выводится как -1.
Строка a * c (int * unsigned int):
* В операции участвуют знаковый int (a = -1) и беззнаковый unsigned int (c = 1).
* Согласно правилам Usual Arithmetic Conversions, если ранги типов совпадают (int и unsigned int имеют одинаковый размер, обычно 4 байта / 32 бита), знаковый тип int неявно преобразуется к unsigned int.
* Число -1 в дополнительном коде (32 бита) представляется двоичным значением 0xFFFFFFFF. При неявном переводе в unsigned int оно трактуется как $2^{32} - 1 = 4294967295$.
* Вычисляется беззнаковое умножение: 4294967295 * 1 = 4294967295.
Результат имеет тип unsigned int и выводится как 4294967295.
2. Замена типов на short и unsigned short
 Работа правила Integral Promotion (Целочисленное продвижение):
  * На современных архитектурах типы short и unsigned short занимают 2 байта (16 бит), в то время как базовый тип int занимает 4 байта (32 бита).
  * По стандарту C++, перед выполнением любых бинарных арифметических операций операнды типов меньше int автоматически продвигаются к типу int, если тип int способен вместить весь диапазон их значений.
  * Диапазон unsigned short ($0 \dots 65535$) полностью помещается в диапазон знакового 32-битного int (от $-2\,147\,483\,648$ до $+2\,147\,483\,647$).

Преобразование операндов:
  * Переменная a (тип short, значение -1) неявно преобразуется в int со значением -1.
  * Переменная c (тип unsigned short, значение 1) неявно преобразуется в знаковый int со значением 1.

Вычисление:
  * Операция a * c превращается в умножение двух чисел типа int: $(-1) \cdot 1 = -1$.
  * Поскольку операнды были продвинуты до знакового int, беззнаковое приведение не происходит.
  * Результат имеет тип int и выводится как -1.

1. Выражение (x / y) / d:
   Первое действие (x / y):
   * Оба операнда x и y имеют тип int.
   * По правилам C++, деление двух целых чисел выполняет целочисленное деление с отбрасыванием дробной части: 7 / 4 = 1 (дробная часть .75 теряется).
   * Результат скобок имеет тип int и равен 1.
   
   Второе действие 1 / d:
   * В операции участвуют int (значение 1) и long double ($d = 0.25$).
   * Согласно правилам Usual Arithmetic Conversions, тип int неявно приводится к наиболее «широкому» типу операнда — long double ($1.0$).
   * Выполняется вещественное деление: $1.0 / 0.25 = 4.0$.
   * Итоговый результат: 4.

2. Выражение (x / d) / y:
   Первое действие (x / d):
   * Операнд x имеет тип int (7), а d — long double (0.25).
   * Переменная x неявно преобразуется к long double (7.0).
   * Выполняется вещественное деление без потери точности: 7.0 / 0.25 = 28.0.
   * Результат скобок имеет тип long double и равен 28.0.

   Второе действие 28.0 / y:
   * Операнд y (int, значение 4) неявно приводится к long double (4.0).
   * Выполняется вещественное деление: $28.0 / 4.0 = 7.0.
   * Итоговый результат: 7.

* Причина различия: В первом случае скобки заставляют C++ сначала выполнить целочисленное деление x / y до приведения к вещественному типу, из-за чего данные теряются на первом же шаге. Во втором случае приведение к long double происходит сразу при делении x / d.

1. Выражение (a * b) * c:
   
   Первое действие (a * b):
   * Оба операнда a и b имеют тип long (предположим, 32-битный).
   * Истинный результат умножения $200\,000 \cdot 200\,000 = 40\,000\,000\,000$ ($4 \cdot 10^{10}$).Показываемое число превышает максимум 32-битного знакового типа ($2.14 \cdot 10^9$). 
   * Происходит целочисленное переполнение (Arithmetic Overflow). Значение обрезается и искажается (например, превращается в -1294967296).
   
   Второе действие [результат переполнения] * c:
   * Искажённый результат умножается на c (long long). Он неявно расширяется до long long, но исходные данные уже испорчены переполнением.  
   * Итоговый результат: Некорректное число (например, -258993459200000).
2. Выражение a * (b * c):
   Первое действие (b * c):
   * В операции участвуют b (long) и c (long long).
   * По правилам Usual Arithmetic Conversions, переменная b неявно приводится к наиболее высокому рангу — long long. 
   * Выполняется 64-битное умножение $200\,000 \cdot 200\,000 = 40\,000\,000\,000$, которое свободно помещается в диапазон long long (до $9 \cdot 10^{18}$).

   Второе действие a * [результат]:
   * Переменная a (long) неявно приводится к long long.
   * Выполняется 64-битное умножение $200\,000 \cdot 40\,000\,000\,000 = 8\,000\,000\,000\,000\,000$ ($8 \cdot 10^{15}$).
   * Итоговый результат: Корректное значение 8000000000000000.


* Причина различия: Изменение порядка скобок определяет, когда именно произойдет неявное приведение типа к более широкому long long. В выражении a * (b * c) приведение происходит до первого умножения, что предотвращает переполнение памяти.

Пояснения для текстового отчёта
Контексты неявного приведения: В Python нет классического арифметического неявного преобразования типов (как в C++ или JavaScript), однако в управляющих конструкциях (if, while) и логических операторах (and, or, not) любое значение проверяется на т.н. истинность (truthiness).

Механизм работы: При проверке условия if user_input Python внутри себя обращается к специальному методу класса строки __bool__() (или вычисляет len(user_input) > 0).

Распространённая ошибка: Строка, содержащая символы "0" или "False", для интерпретатора Python является обычным непустым объектом str с длиной больше нуля, поэтому она неявно преобразуется в True (в отличие от числа 0 или значения None).
